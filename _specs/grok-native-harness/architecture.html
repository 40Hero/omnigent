Grok as a governed Omnigent harness — via ACP

The governed path: acp:grok on the existing generic acp harness. Almost everything is reused; only the shaded pieces are created this bet.

Read it top to bottom. A prompt enters through the acp:grok config (the one thing created), which the generic acp harness resolves into a spawn command. AcpExecutor (reused) opens ACP over grok agent stdio and streams grok's output back as Omnigent events. The governance boundary (dashed gold) is the whole point: when grok asks to run a tool it emits session/request_permission, which AcpExecutor already routes to the CEL policy engine — a DENY blocks the tool before it executes. The two black dots are the only new frozen seams: the acp:grok config schema and grok's ACP dialect against AcpExecutor's expectations. If grok ever self-executes without asking permission, the fallback re-gates via grok's own x.ai/hooks pre_tool_use into the same policy endpoint.
